# CRM Dashboard Load Test

অনেক ইউজার একসাথে **CRM Dashboard** (`/Student/CrmConversation/Dashboard`) খুললে পেজটা ধীর
হয় কিনা — সেটা মেপে দেখার টুল। প্রতিটা ইউজার আলাদা সেশনে (আলাদা কুকি) সত্যিকারের একসাথে লগইন
থেকে একসাথে Dashboard খোলে, আর প্রতিটার সময় মাপে।

## কেন এটা এক্সটেনশন নয়

এক্সটেনশন এক ব্রাউজারের ভেতরে বন্দী, আর **এক ব্রাউজার = একজন মানুষ**: দ্বিতীয় ইউজার লগইন করলে
প্রথমজন লগআউট হয়ে যায় (সাইট প্রতি ব্রাউজারে একটাই সেশন রাখে)। "৫০ জন একসাথে" করতে হলে ৫০টা
আলাদা সেশন লাগে — প্রতিটার আলাদা কুকি-জার। Playwright-এর **browser context** ঠিক তাই: একটা আসল
Chrome-এর ভেতরে N টা আলাদা সেশন, প্রতিটা যেন নিজের incognito উইন্ডো যে অন্যদের সাথে কুকি ভাগ করে
না। তাই N জন একসাথে লগইন থেকে একসাথে পেজ খুলতে পারে — যেটাই আসল টেস্ট।

নতুন ব্রাউজার নামানো হয় না — এটা তোমার মেশিনে **আগে থেকে থাকা Chrome**-ই চালায় (`channel: chrome`)।

## চালানো

```bash
cd crm-loadtest
npm install                     # একবার — playwright-core, হালকা, ব্রাউজার নামায় না

# username,password তালিকা বানাও (users.example.txt দেখো)
cp users.example.txt users.txt  # তারপর আসল অ্যাকাউন্ট বসাও

node loadtest.js --base https://ums-41.osl.team --users users.txt --count 25
```

**হেড দেখতে চাইলে** (ব্রাউজার চোখে দেখা যাবে, headless নয়):

```bash
node loadtest.js --base https://ums-41.osl.team --users users.txt --count 10 --headed
```

সব অপশন: `node loadtest.js --help`

## যা করে — দুই ধাপ

1. **লগইন** — সবাইকে (একসাথে `--count` জন করে) আলাদা context-এ লগইন করায়। কে ঢুকল, কে পারল না
   (ভুল পাসওয়ার্ড / নিষ্ক্রিয় অ্যাকাউন্ট), লিখে জানায়।
2. **একসাথে Dashboard** — যারা লগইন হয়েছে সবাই **একসাথে** Dashboard খোলে, প্রতিটার সময় মাপে।

## সংখ্যাগুলোর মানে

দুই রকম "ধীর" আলাদা করে দেখায়:

| | মানে |
|---|---|
| **server answer** | request পাঠানো → HTML-এর শেষ বাইট ফেরা। **সার্ভার/রান্নাঘর** কত দেরি করল |
| **full page load** | পুরো পাতা আঁকা শেষ হওয়া পর্যন্ত। এর ভেতরে সার্ভারের সময় + **ব্রাউজারে আঁকার** সময় |

আর **একজন একা** বনাম **N জন একসাথে** তুলনা করে বলে দেয় পেজটা চাপে ধীর হয় কিনা — আর হলে সেটা
সার্ভারের দোষ নাকি ব্রাউজারে রেন্ডারের দোষ। `--out numbers.csv` দিলে প্রতি-ইউজারের সংখ্যা একটা
CSV-তেও লেখে।

## লগইন ফর্ম

টুল লগইন ফর্মটা **নিজে খুঁজে নেয়**: সাইটে গিয়ে যদি password বাক্স পায়, সেটাই লগইন পাতা; password
বাক্সের আগের দৃশ্যমান text বাক্সটা username। সাইটের **আসল ফর্ম** পূরণ করে বলে ASP.NET-এর
antiforgery token ব্রাউজার নিজেই পাঠিয়ে দেয় — আলাদা করে সামলাতে হয় না।

খুঁজে না পেলে হাতে বলে দেওয়া যায়:

```bash
--user-field "#UserName" --pass-field "#Password"
```

## পরীক্ষা

`node selftest.js` — একটা নকল UMS (লগইন ফর্ম + antiforgery টোকেন + চাপ বাড়লে ধীর হওয়া Dashboard)
দাঁড় করিয়ে আসল CLI চালায় আর মিলিয়ে দেখে: ঠিক লোকেরা লগইন হলো, ভুল পাসওয়ার্ড আটকাল, N টা আলাদা
সেশন একসাথে টিকল, সময় বেরোল, আর চাপে ধীর হওয়া ধরা পড়ল।

## ⚠️ সতর্কতা

- **আসল অ্যাকাউন্টের পাসওয়ার্ড** `users.txt`-এ থাকে — ওটা git-এ যায় না (`.gitignore`-এ ঢাকা),
  আর কারো সাথে শেয়ার কোরো না।
- এটা একটা **লোড টেস্ট** — সংখ্যা বাড়ালে সার্ভারে সত্যিকারের চাপ পড়ে। প্রথমে ছোট `--count` দিয়ে
  শুরু করো, সার্ভার সামলাতে পারছে দেখে তবেই বাড়াও।

## এক্সটেনশনের Run বোতাম দিয়ে (টার্মিনাল ছাড়া)

CRM · Dashboard কার্ডে **▶ চালাও** বোতাম আছে — চাপলে ফল ওখানেই আসে। কিন্তু এক্সটেনশন নিজে
প্রোগ্রাম চালাতে পারে না, তাই মাঝখানে একটা ছোট **সহায়ক (native host)** লাগে। একবার ইনস্টল করো:

```bash
cd crm-loadtest/host
node install.js          # Chrome/Edge-এ রেজিস্টার করে (admin লাগে না)
```

তারপর এক্সটেনশন **reload** করো (`chrome://extensions` → ↻)। এবার ▶ চালাও চাপলে:
লগইন → একসাথে Dashboard → রিপোর্ট, সব কার্ডেই।

- এক্সটেনশনের **id বদলালে**: `node install.js --ext <নতুন-id>` (id দেখা যায় chrome://extensions-এ বা
  ঠিকানা বারে `chrome-extension://<id>/app.html`)।
- **সরাতে**: `node install.js --uninstall`
- সহায়ক ইনস্টল না থাকলে বোতাম সেটা বলে দেয় — তখন উপরের terminal-এর পথটা তো আছেই।
